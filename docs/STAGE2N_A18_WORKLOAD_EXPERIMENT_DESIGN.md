# 下一阶段负载实验设计（仅矩阵与指标）

日期：2026-09-14。状态：**实验设计**。不授权新 RTL、不 program、不重编 Host/xclbin、不改验收结论。

冻结事实（只引用，不改写档案）：

- A16.2：单 `HBM[0]`，四行顺序查找，功能与周期基线已验收；
- A17.6：四 BO、`HBM[0..3]`、五用例功能 PASS；
- A16/A17 可比性能结论 **未形成**；
- 性能、吞吐、带宽、加速比 **均未宣称**。

文献约束见 `docs/STAGE2N_A17_LITERATURE_REGISTER.md`。本矩阵用来回答「超过四张表 / 可变索引 / 共同访问 / 均匀 / 热点 / Bank 冲突」，**不是** 把现有四槽恒等映射写成创新。

## 0. 当前硅上不能跑什么

A17 集成参数把四槽行号写死为：

```text
slot0 → row 37
slot1 → row 38
slot2 → row 39
slot3 → row 40
```

四张逻辑表、四个 master。因此：

| 目标负载 | 冻结 A16/A17 能否执行 |
|---|---|
| 超过四张表 | **不能** |
| 可变索引 | **不能**（行号在 RTL 参数里） |
| 共同访问（多特征打到同一伪通道） | **不能有效制造**：现行映射是槽 i 独享 `HBM[i]`，且四 BO 拷同一份表 |
| 均匀 / 热点行分布 | **不能**（行固定） |
| Bank 冲突（多请求争用同一 `HBM[i]`） | **不能**（每口一笔、一口一通道、无额外表） |

现有板卡只重复「四固定行 + 恒等映射」的进程重启观测。那不是本矩阵。

分三层，只有 L0 已有硬件；L1/L2 需另一次授权才实现。

```text
L0  冻结 A16.2 / A17.6     → 不可跑本矩阵
L1  本地 Python 痕迹 + 抽象通道模型 → 不碰 RTL/板卡，可先定量冲突
L2  新版本 RTL/Host（未来 A18 类）   → 可编程 table/row、T>4、映射策略
```

## 1. 目标与非目标

目标：在 **仍冻结 A13 计算** 的前提下，定义一组能区分「访存组织」与「BO/Host 条件」的负载，使后续若做放置，必须相对轮转/容量/频次/无共同访问做消融，并与 MicroRec/SCRec/Flips（原文入库后）对照。

非目标：本文件不实现；不宣称加速；不把 n=11 当充分统计；不测功耗；不引入 GPU/集群（FleetRec 那一层）。

## 2. 因子（先冻结定义）

| 因子 | 水平 | 说明 |
|---|---|---|
| T 表数 | 4, 8, 16 | 4 = 与现夹具同宽；8/16 才可能 T>B |
| B 伪通道 | 4（与 A17 相同 `HBM[0..3]`） | 不把实验先扩到 32 通道 |
| 映射 M | ident（槽%B）、rr、cap、freq、coacc | ident = 现实现；后四者仅 L1/L2 |
| 索引 | fixed（`slot0→37` … `slot3→40`）、unif、zipf(α∈{0.8,1.2}) | fixed 只作回归，不是负载实验 |
| 共同访问 C | 独立 / 分组（指定表对同请求共现） | 共现表若映射到同一 Bank 则冲突 |
| 冲突可见性 | 无共享 Bank / 强制 2 表→1 Bank | 用于正对照 |
| Host/BO | 现 A16 整表重填；现 A17 四路恢复+单槽改；L2 按表 BO | 必须当实验条件，不当创新 |

训练/调参用的 traces 与评估 traces 分开（架构审阅 §6）。合成 traces 只验证工具与映射几何，不能代替真实推荐 traces。

## 3. 实验矩阵（设计）

主矩阵（L1 即可跑几何；L2 才有 FPGA lookup）：

| 实验 | T | M | 索引 | C | 目的 | 现硬件 |
|---|---|---|---|---|---|---|
| E0 回归 | 4 | ident | fixed `slot0→37` … `slot3→40` | 无 | 与 A16/A17 功能夹具对齐 | L0 已做，**不要再当新实验** |
| E1 均匀无冲突 | 4 | ident | unif | 独立 | 基线几何：T=B 且 1 表 1 Bank | L2 |
| E2 均匀过订阅 | 8 或 16 | rr | unif | 独立 | T>B，轮转是否均匀摊通道 | L1/L2 |
| E3 热点无共现 | 8 | freq vs rr | zipf 1.2 | 独立 | 高频表是否应独占通道 | L1/L2 |
| E4 共同访问 | 8 | ident vs coacc | unif | 指定共现对 | 共现表同 Bank vs 分 Bank | L1/L2 |
| E5 强制冲突 | 8 | 两热表绑同一 `HBM[0]` | zipf | 共现 | 冲突上限对照 | L1/L2 |
| E6 容量倾斜 | 16 | cap vs rr | unif | 独立 | 大表独占 vs 切分（切分=新机制，默认先不切行） | L1 |
| E7 BO 条件 | 4 | ident | fixed | 无 | 仅改 BO 填充/进程内重复，不改映射 | 若做，用现 Host 协议变体，**单独授权**，不与 E2–E5 混称加速 |

消融（L2 若有放置目标函数才有意义）：去掉共同访问项、去掉实测 Bank 代价、只留容量或只留频次。没有这组消融，不能写「共同访问感知放置」贡献。

顺序：E0 已完成 → L1 先做 E2/E4/E5 的 **冲突计数**（无 FPGA）→ 只有授权 L2 后才在板上报 lookup/e2e。

## 4. 指标（必须分栏）

**已有、可继续用于 E0：**

- 功能：五金标准 `-393/-392/-93/-689/-519`，mask `0xF`，A13 `322/100/744/1174`；
- FPGA：lookup、compute、e2e、residual（同一套 S/A/D/C/F）；
- 报告 min/median/max 与 **全列表**；预热单独存放。

**L1 几何指标（无板卡也能算，不算物理 HBM）：**

- 每请求的 **Bank 碰撞次数**（同一周期窗口内 ≥2 个请求映射到同一 `HBM[i]`）；
- 映射后每通道请求计数的 max/min 比（倾斜）；
- 共现对落到同一通道的比例。

**L2 才允许的板卡指标（授权后）：**

- 仍报 lookup/compute/e2e/residual，按 (T,M,索引,C) 分格；
- 可选：每 master AR 到 R 的诊断计数（不得替换 lookup 定义）；
- Host 墙钟与 BO 同步时间 **另栏**，不进入 FPGA e2e。

**禁止当作本矩阵成功标准：**

- GB/s、QPS、功耗、加速比；
- 用单次或 n=11 进程重启代替稳态吞吐；
- 把 E7（BO 条件）的差异解释成 Bank 映射收益。

Class C 规则仍适用：A16/A17 对比必须先对齐 BO 协议与 lookup 起点 A，再谈区间差。本矩阵的 L2 应在 **同一种** Host/BO 协议下扫 M 和 C。

## 6. 工作量边界

本轮只写到这里。下一步若继续本地整理：L1 可用已有 `analysis/embedding_trace` 一类工具生成合成共现，**仍不改 RTL**。L2 需要单独授权的新版本顶层（可变 table/row、T>4 的聚集），不得改冻结 A13/A16/A17 验收文件。

L1 请求分布检查（2026-09-15，仅本地离线）：见 `docs/STAGE2N_A18_L1_WORKLOAD_ANALYZER.md`。现实现里 `ident`/`rr` 等价；`coaccess` 只是跨表相同行索引构造，不是表共现模型。该工具**不**构成共同访问映射进 RTL 的证据，**不**改本文件的验收边界。

## 7. 真实负载输入契约（设计，未实现采集）

当前硅上与 L1 合成器都**不能**代表真实推荐负载：

- A17 RTL 把四个槽的行号写死为：`slot0→row 37`，`slot1→row 38`，`slot2→row 39`，`slot3→row 40`；
- 每一轮对这四个槽**各查找一次**；
- 四个 BO 拷同一份 1024 字节表，不是四张独立业务表；
- L1 工具同样采用「全表每轮各一笔」，Zipf 只改数字行号，不改每表次数。

在真实 trace 进入之前，不要围绕人工 `coaccess` / `forced_conflict` 再做推导，也不新增映射策略或性能指标。

未来若接入真实负载，一条查找记录至少需要：

| 字段 | 含义 | 当前夹具 |
|---|---|---|
| `request_id` | 一次推理/请求的编号 | **缺**（板上是 Host 五用例循环，不是请求流） |
| `table_id` | 逻辑表编号 | **缺真实集合**；RTL 只有槽 0–3 |
| `row_id` | 该表上的行索引 | 固定 `slot0→37` … `slot3→40`，**不能**代表分布 |
| 每请求每张表的 lookup 次数 | pooling 长度；同一表可多次 | **固定为 1** |
| `embedding vector bytes` | 该次读的向量字节数 | 夹具行宽 16 字节；真实表宽 **缺** |
| 可选：访问时间顺序 | 同一请求内各 lookup 的先后 | **缺**；A17 四口同时发起，A16 则顺序四行 |

没有上表字段，不能讨论不同表的服务负担、共同访问，也不能授权可变索引 RTL。训练/调参 trace 与评估 trace 仍应分开（见上文 §2）。
