# A18 L1 请求分布检查工具

日期：2026-09-15。状态：**本地离线工具**。不是板上实验，不是性能结果，也**不能**证明共同访问映射值得进入 RTL。

实现：`analysis/stage2n_a18_l1/workload_analyzer.py`  
入口：`analysis/run_stage2n_a18_l1_workload_analyzer.py`  
自检：`scripts/check/check_stage2n_a18_l1_workload_analyzer_v1.py`

矩阵定义仍见 `docs/STAGE2N_A18_WORKLOAD_EXPERIMENT_DESIGN.md`。本工具只做 **L1 请求分布 / 几何检查**。

## 固定对照

每轮对全部 T 张表各查一次。不通过跳过表或加入频次策略制造差异。

`ident` 与 `rr` 在本实现中是同一个函数：`bank = table_id % 4`。它们是同一条带基线的两个名称，不能当成两种独立对照。

## 指标（几何，不是物理）

- `concurrency` = 本轮用到的通道数  
- `conflict_count` = 本轮请求数 − 用到的通道数  
- 每轮最大完成时间代理值 = 各通道占用条数的最大值  

三者都不是实测冲突、实测并发或 FPGA 周期。行索引不进入通道占用：占用由「表→通道」映射和「每表一笔」共同决定。

因此 T=8 → 占用 `[2,2,2,2]`、T=16 → `[4,4,4,4]` 是设定直接得到的结果，只作自检，不是研究发现。

`hotspot` 的 Zipf 只改行索引，不改每表请求次数，也不改该计数模型下的通道占用。热点行 ≠ 热点表。

`coaccess` 是 **跨表相同行索引构造**：指定表对共用同一个数字 `row_id`。每轮仍访问全部 T 张表，表集合没有额外共现特征。不同表上的同一行号通常不是同一数据、也不是同一物理地址。两表同通道会有服务竞争，不要求行号相同。`SAME_ROW_INDEX_SAME_BANK` 只说明指定配对落在当前映射的同一通道，不能写成发现了新的共同访问冲突。

强制把表 0、1 钉到通道 0 时，T=8 条带占用是 **`[3,1,2,2]`**：没有闲置通道，只是负载不均衡。此时 `conflict_count` 仍是 `8−4=4`，与均衡占用相同；不均衡要看占用向量，不要看这个差。

## 它不能回答什么

- 不是真实 HBM 时延、排队、刷新或 AXI 互联  
- 不能输出或声称 GB/s、QPS、吞吐、加速比  
- 不能替代 A16/A17 板上 lookup/e2e  
- 不能作为「共同访问感知映射应进 RTL」的证据  
- 不能在冻结 RTL（`slot0→row 37` … `slot3→row 40`）上复现 T>4 负载  

## 下一步需要从真实负载确认的字段

| 字段 | 本工具现状 |
|---|---|
| `table_id` | 合成 `0..T-1`，**缺**真实请求里的表集合与是否每请求全表出现 |
| `row_id` | 合成均匀 / Zipf / E0 固定 `slot0→37` … `slot3→40`，**缺**真实行分布 |
| 每请求每表的查找次数（pooling 长度） | 固定为 1，**缺** |
| 向量字节数 | **未建模** |

没有这些字段，不能讨论不同表的服务负担，也不能论证共同访问映射。
