# Stage 2D runtime quantization and timing review

## Status and evidence boundary

The default `mlp_sequence_controller` configuration now meets the local
10.000 ns OOC synthesis constraint under Vivado 2022.1 for
`xc7a200tfbg484-2`. Functional and backpressure regressions pass, the Stage 2C
banked-memory mapping is preserved, and synthesis reports no errors, critical
warnings, or latches.

This is local post-synthesis evidence. It is not Vivado 2020.2, implementation,
F37X resource/timing, `.xclbin`, or board evidence. The user must perform those
target-version and target-platform steps. Generated DCP, reports, logs, and
work directories remain ignored.

## Pipeline and cycle contract

`runtime_relu_quant` is a two-entry elastic pipeline:

1. stage 1 computes absolute magnitude, runtime rounding bias, and the rounded
   magnitude sum;
2. stage 2 performs the runtime right shift, sign restoration, signed INT16
   saturation, and optional ReLU.

Both stages use ready/valid replacement semantics. A blocked output holds
`out_valid`, data, and error stable. An output consume can refill both stages
on the same edge, reset clears both valid bits, and a full-rate source can be
accepted every clock.

The dense engine holds output index, `last`, tag, descriptor fields, and target
activation-buffer selection until the quantized result is atomically accepted
by both the result FIFO and scalar activation write. A stalled FIFO therefore
cannot produce a partial activation write. `job_done` is generated only by the
final atomic commit; it is not generated by dot-result acceptance or an
intermediate quantization stage.

Relative to Stage 2C, quantization adds two clocks from dot-result acceptance to
FIFO/activation commit for every output neuron. Registering the MAC product
adds one explicit `STATE_MAC_DRAIN` clock per dot product before reduction.
Because this engine processes output neurons serially, an unstalled layer adds
exactly `3*out_dim` clocks: two quantization clocks plus one MAC-drain clock per
output. The fixed-point values, ordering, and external descriptor/result
formats are unchanged.

## Additional timing fixes

The MAC product is registered at the DSP output. The ACC32/ACC48 accumulator
remains a fabric carry-chain sum through a dedicated `use_dsp="no"` net, so the
default design retains 21 DSP blocks instead of temporarily consuming 37.

Weight-provider range handling now derives an error from the highest enabled
lane and registers a per-lane valid response mask. Out-of-range lanes can never
reach response data, while the RAM read port no longer contains a long
address-range comparison. Aligned, unaligned, row-crossing, masked, final-row,
and partial-out-of-range behavior remains covered by the independent provider
bench.

The 16 `4096x8` weight banks and one `1024x24` bias RAM still infer as 17
RAMB36E1 blocks. The two activation buffers still infer as 32 RAMB18E1 blocks;
the 20 LUTRAMs belong to the result FIFO.

The former 32-level descriptor-shift-to-activation-RAM path is gone. The final
worst path is from the registered weight-request address DSP to
`weight_rsp_error_reg`: 12 logic levels, 9.197 ns data delay, and +0.758 ns
slack. The first reported quantization path is also met at +0.770 ns, from the
rounded-magnitude register to the output register.
